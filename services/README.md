# Services

本目录保存 EduGrade 当前实际运行的业务后端与独立计算 Worker。

## 当前架构

`api-gateway` 是 Go 业务后端的模块化单体运行时。认证、组织、考试、试卷、答卷、阅卷、复核、质量、成绩发布、申诉、报告、AI 治理和数学理解等领域能力位于 `api-gateway/internal/*`，通过进程内模块边界组织，并不作为彼此独立的网络微服务部署。

保留 `api-gateway` 这一现有目录名；它同时承担统一 HTTP 入口和核心业务应用运行时职责。

## 独立计算 Worker

以下目录是当前真实存在的独立 Worker：

- `ocr-worker`：文字、手写内容与公式识别任务。
- `page-processing-worker`：页面解码、配准、条码、切题和 OMR 处理。
- `image-quality-worker`：答卷图像质量检测。
- `subjective-grading-worker`：主观题评分任务执行。
- `math-verification-worker`：数学表达式解析与验证。

这些 Worker 独立运行，是因为它们具有不同语言或运行时、资源隔离、长时间异步任务、模型与图像计算、独立扩缩容等实际需求，而不是为了增加微服务数量。

## 服务拆分原则

业务领域默认继续作为 `api-gateway/internal/*` 中的模块维护。只有出现明确的独立运行需求，例如独立扩缩容、独立故障域、独立安全边界、显著不同的资源需求或独立发布生命周期，才考虑增加新的网络服务。

一个业务领域不默认对应一个微服务。新增可部署组件时，必须同时提供真实入口、依赖清单、运行配置、健康检查、部署接线和维护责任。
