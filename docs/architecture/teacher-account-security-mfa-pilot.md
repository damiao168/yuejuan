# TOTP 与操作级挑战管理试点

本切片使用项目现有 Go API Gateway、PostgreSQL / Redis、账号会话、CSRF 和审计，没有增加身份服务或外部二维码服务。

## 范围和明确限制

默认 `EDUGRADE_MFA_ENABLED=false`。这是**验证器管理试点**，不是已经上线的双因素登录：普通登录、成绩发布等业务入口不要求 TOTP，风险处置仍只支持 `off/shadow`，不能将本切片宣传为账号已受强制 MFA 保护。管理端账户安全页现已接入注册、确认、恢复码一次性保存，以及验证与最终操作分开的挑战界面；研究证据、秘密生命周期和上线缺口见 [MFA 交互与风控研究](teacher-account-security-mfa-ux-research.md)。

当前挑战仅支持 `mfa.disable` 和 `mfa.recovery.rotate`。验证成功不会提升整个会话的 `auth_level`、信任浏览器、刷新近期密码认证或降低风险。TOTP 不是抗钓鱼认证，不能替代平台管理员后续所需的 Passkey / WebAuthn 或满足要求的企业 IdP。

## 接口闭环

所有接口均以已认证上下文确定租户和用户，不接受客户端指定操作目标。公共电脑和服务账号不能修改验证器。浏览器 Cookie 请求继续经过现有 CSRF 保护；这些接口直接进行账号认证，**不经过通用幂等回执缓存**，客户端附带 `Idempotency-Key` 也不会保存或重放秘密响应。

| 接口 | 输入与结果 |
| --- | --- |
| `GET /api/v1/auth/mfa` | 可用性、是否确认启用、剩余恢复码数量；不返回密钥 |
| `POST /api/v1/auth/mfa/totp/enroll` | 当前密码；返回一次性注册密钥、本地 PNG 二维码、注册 ID 和 10 分钟到期时间 |
| `POST /api/v1/auth/mfa/totp/confirm` | 同一会话的注册 ID 与 6 位码；确认后仅一次返回 10 个恢复码 |
| `POST /api/v1/auth/step-up/start` | 当前密码与指定操作；返回 5 分钟挑战 ID 和允许的验证方式 |
| `POST /api/v1/auth/step-up/verify` | 挑战 ID、方式、验证码；只验证对应操作，不执行原命令 |
| `POST /api/v1/auth/mfa/recovery-codes/rotate` | 已通过 TOTP 的重新生成挑战 ID；消费授权并作废旧恢复码，仅一次返回新码 |
| `POST /api/v1/auth/mfa/totp/disable` | 已通过 TOTP 或恢复码的关闭挑战 ID；消费授权，移除凭据并撤销全部会话和设备绑定 |

注册只有成功确认后才启用；已启用的验证器不能被新的注册覆盖。待确认注册绑定发起会话和安全版本，改密、恢复、锁定或撤销会话后不能继续确认。关闭验证器后须重新登录，不能重用原会话。

恢复码只能连同当前密码授权关闭验证器，不能重新生成恢复码、提升全局认证等级或授权业务命令。验证阶段立即消费恢复码，即使用户未完成关闭也不能再使用该码。验证码或恢复码响应丢失时不得通过通用重试取回；管理界面提示刷新状态、使用新的动态码／另一条恢复码重新挑战，不自动执行有副作用的原操作。启用或轮换已成功但恢复码响应丢失时，需要通过验证器重新生成新码。

## 存储和并发边界

迁移 `000149_auth_totp_scoped_challenges.sql` 建立 `auth_totp`、`auth_mfa_recovery_code`、`auth_mfa_challenge`，组合外键约束租户、用户和凭据一致，三表启用并强制租户 RLS，授权既有非特权运行角色。

每个用户最多一个验证器。TOTP 使用独立的随机 32 字节密钥进行 AES-256-GCM 加密；附加认证数据绑定版本、租户、用户和凭据 ID，跨用户替换密文也不能解密。没有开发默认密钥，不复用模型凭据主密钥。恢复码每个含 128 位随机熵，仅保存 SHA-256 摘要；挑战令牌和会话关联也只保存摘要。

使用 `github.com/pquerna/otp v1.5.0` 的 HOTP/TOTP 实现：SHA-1、6 位、30 秒窗口、前后最多一个窗口偏差。数据库记录最近消费步长，确认注册也消费步长，同一步长不能用于另一挑战。实现遵循 [RFC 6238 的验证窗口与防重放要求](https://www.rfc-editor.org/rfc/rfc6238)，凭据注册、替换和恢复边界参考 [OWASP MFA Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Multifactor_Authentication_Cheat_Sheet.html)。

所有修改按用户、会话、验证器、挑战的统一顺序加锁，并在同一事务中消费 OTP / 恢复码和更新挑战。最终操作重新检查活跃账号、租户、未锁且未撤销的会话、安全版本、凭据 ID、操作、到期时间与未消费状态；密码验证与注册／挑战保存之间发生改密时，摘要条件不匹配即拒绝。挑战验证不延长原 5 分钟有效期。

每次待确认注册／挑战最多 5 次失败，并复用账号、来源、组合三层失败限速。正确密码发起新注册或新挑战不会清空累积 OTP 失败；只有成功确认或真实验证成功才按既有规则清理账号／组合桶，来源桶保持。新启用、关闭、恢复码使用和重新生成进入个人安全活动投影；审计载荷不写密码、密钥、验证码、恢复码或明文挑战令牌。

## 试点部署与密钥运维

1. 先按项目正常流程备份并在隔离环境应用完整迁移链；文件已存在不代表生产已经迁移。
2. 生成独立随机密钥，通过 `EDUGRADE_MFA_MASTER_KEY` 或 `EDUGRADE_MFA_MASTER_KEY_FILE` 提供其标准 Base64 表示；两种来源不能同时非空。限制密钥文件读取权限，禁止进源码、日志和前端配置。配置加载在试点启用但缺少有效 32 字节密钥时失败关闭。
3. 密钥丢失将导致已有验证器无法解密。备份和恢复演练必须同时覆盖数据库与独立密钥；本轮没有在线主密钥轮换工具，不能直接改环境变量并假设旧密文可读。后续需要受控重加密和密钥版本管理。
4. 保持风险影子模式、业务 MFA 关闭，仅在明确告知试点性质的合成账户中联调。前端一次性保存流程已有实现和合成浏览器验证，但仍须完成真实学校恢复演练、独立安全通知、管理员策略、退出／会话失效测试及密钥运维审计，才能评估强制 MFA。
5. 普通改密或管理员协助密码恢复不删除已经启用的验证器。丢失验证器且丢失所有恢复码的人工核验／重新绑定流程尚未交付；不能用密码恢复直接绕过未来的 MFA 策略。本轮无登录 MFA，因此该情况不会阻断普通教师业务登录。

## 验证入口

`internal/auth/mfa_test.go` 覆盖 RFC 验证向量、密文完整性与身份绑定、注册会话／安全版本、挑战范围／有效期／尝试数、并发防重放、恢复码用途及关闭后撤销。`mfa_http_test.go` 覆盖主动提供幂等键时秘密仍不缓存、验证及最终命令仍不能重放。

`internal/server/e2e_mfa_test.go` 使用随机隔离 PostgreSQL 数据库与临时非特权登录角色，验证完整迁移、真实接口、Cookie CSRF、三表 RLS、SQL 事务并发消费、恢复码轮换、审计脱敏及全会话／设备撤销。运行于 `services/api-gateway`：

```powershell
# 使用仅用于隔离测试、具有创建数据库权限的管理连接；不要把凭据提交到仓库。
$env:EDUGRADE_E2E_DATABASE_URL = '<隔离测试管理连接>'
go test -p 2 ./internal/server -run '^TestTOTPManagementE2EWithPostgres$' -count=1 -v
```

测试只使用合成账户，结束时清理随机数据库和临时登录角色，不操作既有开发或生产账户。

### 2026-09-14 安全通知前置切片

- MFA 启用、恢复码使用、恢复码替换和 MFA 关闭现在与脱敏审计、版本化语义 outbox 事件、`awaiting_channel` 通知待办在同一事务提交。恢复码使用按验证成功记录，不等待最终关闭命令；拒绝、过期、租户不匹配和重放不产生安全事实。
- 通知事实不含密码、密钥、OTP、恢复码、挑战／会话摘要、IP、用户代理和联系方式。`auth_mfa` outbox 聚合与通知待办均受强制租户 RLS 保护；请求作用域不能篡改或删除已提交事实，运行身份不能更新或删除 append-only 待办。
- 隔离 PostgreSQL 专项故意阻断通知待办写入，恢复码替换和挑战消费随事务回滚；解除故障后同一已验证挑战可安全执行一次。正常路径核对五个安全事实（含两次替换）、五个待办、审计关联、并发单赢家、租户隔离和 payload 脱敏；还通过真实 outbox store 标记一个事实已发布，确认通知待办仍保持 `awaiting_channel`。
- 当前 outbox 发布器仍只写结构化日志，不能视作站外通知或送达。真实联系人验证、渠道适配、每收件人／渠道幂等投递、退信与运营告警仍是启用门槛；MFA 和动态风险强制处置保持关闭。
- 本机 Go 配置为 `CGO_ENABLED=0` 且没有 C 编译器，因而无法执行 `go test -race`；本轮并发单赢家测试和 PostgreSQL 行锁回归均通过，但支持 CGO 的 CI race 仍是合并及启用前门槛，不能以本机结果替代。
