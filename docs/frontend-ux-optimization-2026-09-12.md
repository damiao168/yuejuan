# EduGrade 全身份前端体验优化方案

版本：2026-09-12。对象：产品、设计、前端、后端、测试及学校试用负责人。

本方案基于当前工作目录中的路由、身份映射、页面 JSX、共享组件、CSS 与流程代码检查，并参考可访问性规范、界面设计资料和人机交互论文。**本次交付为优化方案，没有修改业务界面，也没有进行登录后的浏览器实测或真实用户实验。** 工作区存在进行中的修改，因此代码位置代表本次读取时的状态。

“完整”指覆盖目前识别到的生产入口、考试内子模块、共享交互、学生端与桌面端；不是宣称所有动态页面状态已经过实机穷举。文中的尺寸、目标和布局为建议基线，需要用真实中文内容、学校设备和业务数据验证。

## 1. 先解决什么

推荐顺序：**评分与题目对应正确 → 提交与发布边界清楚 → 文字可读 → 工作区不拥挤 → 跨模块操作连续 → 视觉细节统一。**

当前已经具备可复用基础：共享颜色令牌、响应式表格、考试阶段导航、阅卷草稿、独立复核、权限过滤、成绩发布质量检查。优化应沿着这些能力补齐，不应把它们全部当成缺失功能重做。

优先级定义：

| 优先级 | 含义 | 交付原则 |
|---|---|---|
| P0 | 可能导致错误评分、题目错配、发布误解，或身份入口不可达 | 先做定向复现与修复；涉及规则的变更需业务确认 |
| P1 | 高频任务阅读困难、定位困难、流程中断 | 首轮体验改造完成 |
| P2 | 低频配置、分析效率、视觉一致性 | 在核心流程稳定后完成 |

## 3. 设计资料与论文如何用于本项目

以下是规范、行业资料、研究论文三类不同证据，不能互相替代。本方案的具体像素值是项目建议，不是声称论文证明了“所有系统必须用 16px”。

| 来源 | 可以采用的结论 | 本项目应用与边界 |
|---|---|---|
| WCAG 2.2 | 可访问性需有明确、可测试的基线 | 普通文字对比度至少 4.5:1；大字满足条件时至少 3:1。文字放大到 200% 不丢内容或功能；一般内容在 320 CSS px 宽度下重排。二维表格、图像等有适用例外，但不能借此让整个页面横向滚动。参见 [对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[文字缩放](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)、[重排](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) |
| WCAG 2.2 目标与拖拽 | 小目标和精细拖拽应提供可操作替代 | AA 目标大小条款通常要求至少 24×24 CSS px，存在间距等例外；本项目主动采用主要触控目标 44×44px。框选支持两点点击和数值输入，排序支持上下移动按钮。参见 [目标大小](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[拖拽替代](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html) |
| Ant Design 字体规范 | 14px / 22px 是其业务系统基础文字建议 | 现有组件可从这一基线对齐；中文长评分标准、教师长时阅读与学生端正文采用 16px / 26px 作为试用版本。参见 [Ant Design 字体](https://ant.design/docs/spec/font-cn/) |
| Nielsen, 10 Usability Heuristics | 状态可见、一致性、防错、减少回忆负担、帮助用户恢复 | 考试上下文常驻；禁用原因可见；任务直达；错误给下一步；普通连续评分避免重复确认弹窗。参见 [原始作者机构资料](https://www.nngroup.com/articles/ten-usability-heuristics/) |
| Scaltritti 等，2019，Scientific Reports 9:12711 | 在真实网页材料中联合研究字号、间距和空间布局对眼动与阅读的影响；支持一起评估排版变量 | 字号提高时同步调整行高、列宽和信息量。该研究包含意大利语读者，不能直接推出中文阅卷的唯一最优字号。参见 [论文](https://doi.org/10.1038/s41598-019-49051-x) 与 [大学存档全文](https://boa.unimib.it/retrieve/e39773b6-7b67-35a3-e053-3a05fe0aac26/Scaltritti_et_al-2019-Scientific_Reports.pdf) |
| Amershi 等，2019，CHI，Guidelines for Human-AI Interaction | 提出并评估人机 AI 交互指南，强调能力边界、反馈与纠正 | AI 分数与教师最终分分区；说明不确定性；支持纠正、追踪与人工接管；不把模型分数装饰成最终结论。参见 [Microsoft Research 论文页](https://www.microsoft.com/en-us/research/publication/guidelines-for-human-ai-interaction/) |
| Buçinca、Malaya、Gajos，2021，CSCW，To Trust or to Think | 199 人实验中，促使用户主动思考的设计减少了相对简单解释界面的过度依赖，但也带来较低主观体验评价 | 仅在盲评、重大分歧、低置信等必要场景先独立评分再显示 AI；不让所有题都经历强制等待或确认。对教育阅卷的收益仍需实验。参见 [作者论文页](https://www.eecs.harvard.edu/~kgajos/papers/2021/bucinca2021trust.shtml) |

## 4. 所有身份的入口与信息架构

身份数来自注册表，实际可达性仍受角色、权限和数据范围影响。桌面操作员是使用场景，不新增一个未经授权的后端身份。

| 身份 | 首页首先回答的问题 | 建议一级入口 | 默认数据范围 |
|---|---|---|---|
| 平台管理员 platform | 哪所学校、哪项服务需要我处理？ | 平台总览、学校管理、模型配置、模型治理、系统运维、操作记录 | 平台授权范围，进入学校配置明确显示学校上下文 |
| 机构管理员 tenant_admin | 哪所学校卡住，谁可以处理？ | 机构总览、学校与管理员、考试、统计、操作记录 | 当前机构；增加学校能力需匹配服务端授权，不复用平台权限 |
| 学校管理员 school_admin | 哪场考试现在需要操作？ | 工作台、考试、成员、成绩与复核、操作记录 | 当前学校 |
| 考试负责人（职责） | 我负责的考试下一步是什么？ | 我的考试、考试工作区、相关报告 | 由现有管理账号与考试级授权承载，不作为独立登录角色；只能访问本人明确授权的考试 |
| 教师 teacher | 班级有什么需要讲评，我有哪些待办？ | 我的工作、我的阅卷、班级成绩、学生反馈 | 任教班级、分配任务；阅卷按匿名规则 |
| 阅卷员 grader | 我下一份该阅哪题？ | 我的阅卷、已提交记录、账户 | 分配给本人的匿名任务 |
| 仲裁员 arbitrator | 哪些差异需要我裁决？ | 我的仲裁、已完成、账户 | 授权的仲裁任务 |
| 审计员 auditor | 如何找到这次变更的完整证据？ | 审计总览、操作记录、授权导出 | 只读授权范围 |
| 学生 student | 我的成绩如何，哪里失分，怎么复核？ | 我的考试、成绩详情、逐题复盘、复核进度 | 本人已发布且获准展示的数据 |
| 桌面采集 / 离线阅卷场景 | 文件是否传完，草稿是否真的同步？ | 答卷导入、任务队列、离线阅卷、诊断、账户 | 跟随登录者权限与设备能力 |

导航规则：

1. 一级菜单只放跨考试、跨任务入口；进入考试后使用考试阶段导航，不再同时展示大量重复子菜单。
2. 考试工作区保留“准备 → 采集与处理 → 阅卷与质检 → 成绩发布 → 复核与报告”的阶段层级。具体 13 个 section 继续存在，按阶段组织；是否可操作由服务端状态决定，不由视觉顺序决定。
3. 全局页标题 24px，考试名称与学校保持可见；小屏顶栏也要有当前页名，不能只留下汉堡按钮。
4. 多身份切换常驻账户菜单；切换后显示当前身份与学校，独立保存各身份上次页面与筛选，清理跨范围选中记录。草稿处理先保存或明确提示。
5. 教师与阅卷员不出现模型供应商、部署、租户策略等技术入口。高级身份应有独立管理入口，不能污染阅卷主面板。
6. 全局列表打开考试后，返回时恢复原筛选、页码和滚动位置；任务链接必须定位到对应任务。

## 5. 字号、间距、控件的统一规格

### 5.1 文字规格

下列 CSS px 是 100% 缩放下的设计参考值，实施时使用 rem 和语义令牌；尊重浏览器默认字号，不锁死根字号。

| 用途 | 管理端建议字号 / 行高 | 教师 / 学生建议 | 限制 |
|---|---|---|---|
| 页面标题 | 24 / 32 | 24 / 32，小屏 22 / 30 | 同页一个 H1；长名称可换行 |
| 一级模块标题 | 18 / 26 | 18 / 28 | 不用放大卡片数字取代标题 |
| 二级小标题 | 16 / 24 | 16 / 26 | 与正文靠字重区分 |
| 菜单、筛选标签、按钮 | 14 / 22，偏好大字可16 / 24 | 15–16 / 24 | 文案不缩小挤入固定宽度 |
| 表格正文 | 14 / 22 | 教师常用表15 / 24；学生列表16 / 26 | 关键字段禁止 12px |
| 普通说明 | 14 / 22 | 16 / 26 | 中文长文本默认左对齐 |
| 评分标准、评语、题目正文 | 16 / 26 | 可切18 / 30 | 不压缩行高；公式给足上下空间 |
| 时间、版本、非关键辅助文字 | 12 / 18 或13 / 20 | 13 / 20 | 不承载错误原因、下一步操作等关键内容 |
| 图表坐标与标签 | 13 / 20 | 14 / 22 | 小屏减少刻度，不能缩成 10px |
| 评分输入 / 成绩主值 | 28 / 36 | 32 / 40 | 满分、单位至少16px；数值等宽对齐 |
| 错误与阻断原因 | 14 / 22 | 16 / 26 | 文字+图标，不能只靠颜色 |

中文字体建议使用系统无衬线栈，统一管理端、学生端、桌面端。正文 400，标签 500，标题 600；不依赖不同系统可能表现不同的 650/750 作为唯一层级依据。学号和数字采用 `font-variant-numeric: tabular-nums`，只对日志和原始配置使用等宽字体。

“舒适 / 紧凑”优先改变行高和空白，不把紧凑模式变成小字模式；教师增加“大字阅读”偏好。AI 解释与原图缩放是两个独立设置，不能用网页整体缩小让三栏勉强装下。

### 5.2 布局尺寸

| 元素 | 建议 | 验收重点 |
|---|---|---|
| 页面边距 | 桌面24px，普通笔记本16–20px，手机16px | 首屏不给重复标题和说明占据大面积 |
| 主导航 | 保留现有192/64px方案先验证；长身份文案必要时扩到208–224px | 不为少量长字默认挤压整个工作区 |
| 基础间距 | 4、8、12、16、24、32px | 相关字段8–12px，不同任务区24–32px |
| 管理端表单控件 | 默认40px高，紧凑36px | 出错提示展开后不覆盖下一字段 |
| 移动端 / 评分主按钮 | 至少44px高，建议44–48px | 图标可16–20px，但点击区域独立达标 |
| 表格行 | 默认48px，双行64px；紧凑40–44px | 使用最小高度，可随换行增高 |
| 表单宽度 | 单列480–640px，标签放上方 | 仅强相关短字段并排，大段文本整行 |
| 抽屉 | 简单查看480–640px，复杂编辑720–960px，小屏全宽 | 不能让复杂试卷编辑套进窄抽屉 |
| 阅读区域 | 长文约30–42个汉字每行作为试验起点 | 不使用固定字符宽限制扫描图、公式和表格 |
| 滚动 | 普通页一个主滚动区；阅卷允许画布与评分面板独立滚动 | 可见滚动提示，焦点不被固定操作条遮挡 |

宽度适配按**工作区容器宽度**决定：足够宽时使用任务列表+原图+评分面板；中等宽度先收起任务列表；窄屏使用“作答 / 评分 / 证据”切换。图像仍允许局部平移缩放，表单和状态文字保持正常可读尺寸。

### 5.3 配色与状态

蓝色用于当前选中和主要动作；绿色表示流程成功；橙色表示需关注；红色用于失败或阻断。答卷红色批注是业务语义，可保留，但应与系统错误提示的空间位置、图标和标签区分。

例如“识别失败”旁要有“重试识别 / 查看原因”，不能只出现红点。不要对所有正常记录放绿色徽章；正常状态可以用普通文字，让异常真正突出。错误信息及占位文字也要检查文字对比度。

本次按WCAG相对亮度公式计算静态色值：`#98a2b3`对白色约2.58:1，`#94a3b8`对白色约2.56:1；二者不适合作为白底普通业务小字。`#667085`对白色约4.97:1，`#646a73`对白色约5.45:1，可作为候选。这里只验证了指定色值组合，实际元素仍需检查背景、透明度、状态和最终计算颜色；不是宣称整页对比度测试已通过。

## 13. 所有模块共同遵循的操作规则

### 13.1 用户永远知道自己操作哪个对象

学校、考试、科目、题目、答卷、发布版本是不同层级。切换上层对象后，下层选择、请求、缓存、AI建议、表单与成功提示必须按同一上下文更新。请求成功也必须检查其是否仍属于当前对象。

例如学生先点第12题再点第13题，第12题较慢返回时，只能进入第12题缓存，不能改写当前第13题显示；“申请复核”按钮只有当前详情与题号一致时才可用。

### 13.2 所有保存与提交有明确语义

| 操作 | 页面需要告诉用户 | 失败后 |
|---|---|---|
| 自动存草稿 | 正在保存 / 已保存于本机 / 已保存到服务器 | 保留内容与重试，不显示虚假成功 |
| 提交评分 | 当前答卷已提交，是否进入下一份 | 检查实际服务器状态，避免重复提交 |
| 标记异常 | 只是记录问题，还是移出我的队列 | 保留作答与草稿，说明下一责任人 |
| 教师复核建议 | 提交的是建议，不直接发布成绩 | 可返回继续修改未提交建议 |
| 发布成绩 | 哪场考试、哪些学生、公开什么、版本几 | 留在发布页显示确切失败与已完成范围 |
| 撤销 | 撤销的是当前编辑还是已经生效的业务结果 | 无服务端支持不能伪造“撤销提交” |

### 13.3 防错与效率兼顾

仅在正式发布、停用、解除绑定、批量覆盖、退出存在未保存内容等高影响操作提供有信息量的确认。日常保存、选题、连续评分不逐次弹窗。禁用动作旁给短原因，复杂原因可展开；无权限的全局功能可以不显示，但通过外链到达时要有可理解的拒绝页面。

评分不能把“没有输入”和“0分”混为一谈。批量操作说明“本页20条”还是“全部匹配368条”。部分失败返回逐项结果；重试复用同一操作标识或服务端幂等策略，而非无条件重放。

### 13.4 技术文案翻译

| 当前可能出现的术语 | 建议默认文案 | 技术层保留 |
|---|---|---|
| Rubric | 评分细则 | 版本、原始结构 |
| OCR | 文字识别 | OCR引擎与置信指标 |
| registration | 图像对齐 / 身份匹配，按实际功能区分 | 配准矩阵、匹配分数 |
| dead letter | 多次失败，需人工处理 | 队列名与重试次数 |
| confidence | 模型置信度，未校准时明确不是正确率 | 原始字段与校准版本 |
| tenant / deployment | 机构 / 模型部署，仅对应管理者展示 | ID与技术配置 |
| finalized | 已汇总 / 已确认，以真实状态含义选择 | 后端状态码 |

### 14.1 公共组件改造

| 各端CSS | 按壳、列表、表单、画布、图表划分样式；每类组件有清晰断点 | 后续全局覆盖造成其他页退化 |

代码示意仅表达语义命名，不是已修改内容：

```css
:root {
  --eg-font-body: 0.875rem;        /* 默认根字号16px时为14px */
  --eg-line-body: 1.375rem;
  --eg-font-reading: 1rem;
  --eg-line-reading: 1.625rem;
  --eg-font-label: 0.875rem;
  --eg-font-caption: 0.8125rem;
  --eg-font-title: 1.5rem;
  --eg-control-height: 2.5rem;
  --eg-touch-height: 2.75rem;
}
```

不要用全局 `* { font-size: 16px !important; }`，也不要只改 Ant Design 的 fontSize 却忽略原生表格、SVG图表和独立学生端。调整后需核对长中文标签、按钮换行与真实计算样式。

### 14.2 分批交付

| 批次 | 交付内容 | 放行条件 |
|---|---|---|
| 第一批：准确性与入口 | E04–E10定向验证与修复；评分模式与快捷键；题目详情竞态；掌握文案；任务直达 | 关键回归场景全部通过；身份模型疑点得到后端/业务结论 |

### 15.2 各身份代表任务

| 身份 | 试用任务 | 成功判定 |
|---|---|---|
| 平台管理员 | 找到一所学校的模型连接失败并查看配置 | 不切错学校，能说明失败发生在连接还是评分阶段 |
| 机构管理员 | 找到某校管理员并查看该校进行中的考试 | 不获得其他机构数据，不进入错误学校 |
| 学校管理员 | 新建含两个科目的考试，处理一份模糊答卷，再发布结果 | 对象数量正确；异常解决；明确学生可见范围 |
| 考试负责人 | 进入被授权考试修正评分细则，尝试访问未授权考试 | 授权任务可完成，越权入口被正确拒绝 |
| 教师 | 从班级报告定位一题，处理一条学生反馈 | 不把独立复核建议当成已发布改分 |
| 阅卷员 | 连续阅20份，包括0分、手工调整、异常、断网后恢复 | 无错题、丢稿、重复提交；知道保存层级 |
| 仲裁员 | 查看指定分歧并提交最终裁决 | 依据、版本、最终分和后续状态一致 |
| 审计员 | 检索某次改分并导出相同范围记录 | 条件、时区、对象、导出范围可核对 |
| 学生 | 手机查看失分题、放大原作答、申请复核、查看进度 | 题目与图像一致，申请绑定正确题目与版本 |

### 15.3 建议量化目标

以下为拟定验收目标，不是本次已测结果，更不是论文给出的普适阈值：

- P0场景：错题详情、错误分值模式、重复提交、草稿丢失在规定回归集内为0；这不能证明生产绝无错误。
- 一般任务：代表性试用任务完成率目标≥95%，记录样本数、失败原因与置信局限；首轮小样本用于发现问题，不能直接做总体推断。
- 导航：从角色首页到明确待办≤2次激活；具体任务卡一次直达。
- 阅读：核心正文/状态按令牌达标；对比度达标；200%放大下控件和内容不丢失；复杂二维内容仅在自身区域滚动。
- 阅卷效率：在同题难度、相近经验、相同网络条件下对比旧版；单题操作耗时目标下降20%，评分错误不得增加。20%为项目探索目标，基线测量后再校准。
- 主观体验：每任务记录1–7分易用度，配合访谈询问“哪里需要停下来想”；不要只问是否好看。
- 教师试用覆盖不同年龄、经验与视力情况；学生端覆盖手机用户；一轮改造后用不同用户再验证学习成本。

### 15.4 必要自动化回归

1. 评分点不足9个时，越界数字键不意外设置总分；0分与未输入分别验证；鼠标与快捷键生成一致评分结果。
2. 中文输入法组合、弹窗打开、按键重复触发时不提交背景任务。
3. A题慢返回、B题快返回、切考试、卸载页面等情况下，详情与申诉题号始终一致。
4. 保存/提交超时、服务端已成功但客户端未收到响应时，恢复操作不重复写入。
5. 多身份、考试负责人授权与无权限外链；不同学校缓存与选择状态隔离。
6. 移动端表格分页、排序、筛选、选中与桌面业务能力一致；焦点顺序正确。
7. 成绩发布前门禁、发布预览、修订版本、复核结论与学生可见内容一致。

视觉验收再补截图比较、真实计算字号、焦点可见与滚动遮挡检查。静态扫描只能帮助发现疑点，不能代替登录实测与学校试用。

## 16. 页面覆盖说明与边界

- 生产路由：工作台、账户安全、学校、模型配置、考试列表/创建、试卷、采集、阅卷、仲裁、成绩、报告、申诉、学生/班级/教师、初始化、治理、主观题批次、运维、审计均已分配方案。
- 考试内部：overview、students、paper、questions、template、capture、processing、grading、quality、scores、appeals、reports、settings 均由A12–A30及阅卷/质检模块覆盖。路由列表实际为13项；业务阶段导航可以聚合呈现，不能以阶段数量替代真实模块数量。
- 辅助工作区：图像质检、配准纠错、原卷监控、回评、重评、批注、常用评语、试评、标准卷、作答分组、模型评测/批准/评分保障均已包含。
- `QualityDashboardPage` 及 `/quality`、`/permissions`、`/settings` 等标记mock的独立入口按路由配置属于演示/未生产启用范围；统一遵循字号与状态规则，但不把它们列为已完整上线的生产能力。真实考试内quality不同于mock全局quality。
- `ModulePage`、错误边界、无权限与未找到页面按公共状态模块处理；预留教师目录不另造一套设计规范。
- 模型新版本、通知、离线能力、考试负责人授权等需后端支持的增强，在功能真实可用前不能出现误导性可操作入口。
