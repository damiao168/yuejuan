# STORY-061 多厂商原生模型治理、影子评测与策略中心

## Status

Foundation Complete / Expansion Paused（2026-07-30：STORY-061A、061B0～061B0.3C、061B1A 沙箱准入门禁、061B1B 原生 fixture 传输接缝、061B1C1 持久化审批治理及 061C1～061C2 离线评测证据与可见评测中心已完成实现复审。仍未接入任何外部厂商。061C3 题型级批准、061B1C2 真实沙箱联调、生产路由和更多厂商接入暂停，先推进 STORY-062～067 的学校试点主链；待 `V-GOLD`、厂商账号、有效审批和全部合规材料齐备后再恢复。）

## First-principles decision

本 Story 由三条不可妥协的判断决定：

1. **第三方 API 是可替换推理资源，不是产品竞争力。** EduGrade 的竞争力必须来自评分标准结构化、真实答卷处理、证据可追溯、异常复核、教师裁定数据和学校交付能力。
2. **多厂商不等于多条业务链路。** 浏览器、考试、题目、Rubric、阅卷和成绩模块只能依赖 EduGrade 自己的评分契约；厂商差异必须收敛在内部模型网关。
3. **外部模型只能产生候选建议。** 未经题型级评测、批准和人工复核，任何厂商输出都不能写入最终成绩、改变发布状态或面向学生展示。

## Product positioning

产品定位不是“接入多家大模型自动打分”，而是：

> 为学校提供可配置、可执行、可审计的统一评分体系；系统根据题型、数据敏感度、质量、成本和时延选择本地或外部模型，只把不确定结果交给教师。

产品护城河由以下资产组成：

- 版本化 Rubric、评分点、部分得分规则和扣分规则。
- 等价表达、典型答案、常见错误和教师统一裁定。
- 答案原文/原图证据与评分点的可回放关联。
- 本地与多厂商在真实授权冻结集上的题型级表现记录。
- 教师接受、改分、仲裁和申诉形成的反馈闭环。
- 学校级隐私、预算、路由、发布和审计策略。

## User outcomes

- 平台管理员：在“模型策略中心”管理多个厂商的原生接入、能力、部署区域、健康状态和密钥引用，不在页面或数据库明文保存密钥。
- 租户管理员：决定学校是否允许外部模型、允许外发文本还是裁剪题块、可用厂商、预算上限和故障回退方式。
- 考试负责人：为考试选择已批准的模型策略，开考前看到数据外发说明、预计成本和适用题型，不直接编辑提示词。
- 教研负责人：在冻结集和样卷上比较本地模型与多个厂商的建议分、证据、严重错误、教师接受率和成本，按题型批准或撤销模型。
- 阅卷教师：看到统一格式的 AI 建议、评分点证据、来源模型和风险原因；模型分歧、OCR 风险和评分标准外表达进入集中复核队列。
- 运维人员：按厂商、模型、租户、考试和题型查看成功率、超时、限流、P95 时延、Token/计量单位、费用和显式回退记录。

## Existing capability and real gaps

### Reuse

- `contracts/grading-agent/v1` 已建立身份隔离、候选分、证据和版本链边界。
- `ai-services/grading_agent` 已有结构化输出、证据校验、分数重算、幂等、超时、重试和提示词哈希锁定。
- Go API 只调用内部 grading-agent，浏览器不直连模型服务。
- 主观题结果保持 `human review required`，不会直接写最终成绩。
- 审计、Worker Runtime、人工复核和仲裁已有基础设施。

### Gaps

1. 模型执行器仍绑定本地 `LocalLlamaCppAdapter`。
2. Go 响应校验硬编码 `local_llama_cpp` 和 `local-pilot-v1`，无法表达多厂商能力和独立批准状态。
3. 当前只有单一模型 URL、名称和密钥配置，没有供应商、部署、凭据引用和租户策略模型。
4. 没有题型级模型评测、promotion/revocation、影子对比和厂商分歧事实。
5. 没有每次调用的成本、配额、限流、数据区域和回退原因记录。
6. 没有面向学校的外部数据授权界面，无法说明哪些数据会离开本地环境。
7. 教师修正虽可审计，但尚未形成“模型建议—教师最终裁定—修改原因—Rubric 版本”的可查询质量资产。

## Dependencies and sequencing

- 061A 的供应商中立治理地基可以立即实施，不依赖任何外部厂商账号。
- 真实厂商影子评测前，必须存在稳定的 `answer_segment_answer` 生产链路、可回放 OCR/题块证据、完整 Rubric 和经授权的冻结评测集。
- 缺少上述任一输入时，只允许协议 fixture 和合成数据验证，不得宣称模型效果已验证。
- STORY-060 的花名册完整性和发布门禁继续是最终成绩前置条件；本 Story 不绕过或替换这些门禁。
- 供应商采购条款、数据区域、数据留存和“不用于训练”约定未经批准时，该供应商只能保持未启用状态。

## Protocol decision

### External providers

- 外部厂商必须通过各自的**原生官方 API/SDK 或原生 HTTP 协议**接入。
- 不使用 OpenAI-compatible 兼容接口、兼容代理或把所有厂商伪装为同一种外部协议。
- 每个厂商拥有独立 Adapter，负责原生鉴权、请求格式、结构化输出能力、文件/图片能力、错误码、限流信息、用量和请求标识转换。
- 不为追求统一而丢弃厂商特有能力；特有能力通过 capability 声明和受控扩展字段表达。

### Internal contract

- EduGrade 内部继续使用自有、供应商无关的 `GradeRequest -> GradeSuggestion` 契约。
- 业务模块不得出现厂商名称、厂商 SDK 类型或厂商错误码。
- Go API 仍只调用内部 grading-agent；外部密钥永不进入浏览器和业务请求。
- `grading-agent-v1` 保持兼容；多厂商遥测、能力和路由事实通过向后兼容演进或新版本契约承载，不直接破坏已接受的 v1 不变量。

### Local model

- 现有本地 llama.cpp 链路作为 `local` provider 保留。
- “外部厂商不得使用 OpenAI-compatible”不要求立刻重写现有本地运行时协议；本地推理协议属于内部部署实现，不作为第三方厂商接入规范。
- 本地和云端模型必须分别评测、批准、计量和回滚，不能因为模型家族名称相同而视为同一部署。

## Product modes

学校或考试只能选择管理员已批准的策略模板：

| 模式 | 行为 |
| --- | --- |
| `local_only` | 只使用本地模型；失败或不支持时进入人工队列 |
| `shadow_compare` | 正常人工阅卷，同时并行采集一个或多个模型建议；不影响教师分数 |
| `cloud_suggestion` | 已批准的外部模型向教师提供建议，教师可接受或拒绝 |
| `hybrid_escalation` | 本地先处理，满足明确风险规则时才升级到外部模型 |
| `dual_provider_review` | 高风险题由两个独立部署给出建议，分歧超过阈值进入人工仲裁 |

本 Story 不提供“模型输出直接成为最终成绩”的模式。

## Supported scope

### 1. 供应商注册与能力目录

建立以下产品概念：

- Provider：厂商及原生驱动类型。
- Deployment：具体模型、版本、区域、模态、上下文、结构化输出和计量方式。
- Credential Reference：外部密钥管理系统或部署 Secret 的引用；不保存可回显明文。
- Capability Profile：支持学科、年级、题型、文本/图片、最大输入、证据模式及已知限制。
- Health State：可用、降级、限流、停用和未验证。

供应商注册不等于可用于阅卷；只有通过题型级 promotion 的 Deployment 才能进入教师建议策略。

### 2. 厂商原生 Adapter

定义内部 Provider Adapter 接口，但每个实现使用厂商原生协议：

- 原生鉴权与请求签名。
- 原生文本、图片和结构化输出表达。
- 原生请求 ID、限流、错误和用量转换。
- 严格超时、最大响应体和并发限制。
- 供应商响应标准化为内部候选评分。
- 原始响应只按最小必要原则保留；默认保存 hash、版本、用量和验证结果，不保存包含学生答案的完整日志。

首批实施目标为至少两个文本模型厂商和一个具备题块图片能力的多模态厂商；具体厂商由独立选型记录和授权账号决定，不在本 Story 文档中写死。

### 3. 模型策略与路由中心

路由维度至少包括：

- 租户/学校是否允许外部模型。
- 学科、年级、题型和题目风险等级。
- 文本、公式、图形、表格等模态需求。
- OCR 质量、答案完整度和提示注入风险。
- Deployment 的题型级批准状态。
- 单题/单卷/单考试预算。
- 厂商健康、限流、并发和 P95 时延。
- 本地优先、指定厂商、双模型或禁止外发。

路由结果必须可解释，记录“为什么选择该模型、为什么升级、为什么回退”。禁止无记录的静默切换。

### 4. 数据最小化与外发授权

- 外部请求不得包含姓名、学号、班级、学校名称、历史成绩、最终成绩或其他不必要身份字段。
- 默认只允许发送单题的脱敏文本、题干、Rubric 和必要上下文。
- 公式、几何、表格、化学式或低 OCR 质量场景经策略明确批准后，才允许发送裁剪后的题目/答案区域。
- 禁止发送整张答卷或与当前题无关的页面。
- 外部数据是否用于供应商训练必须在采购/协议和配置中明确为禁止；学生数据默认不用于任何训练或微调。
- 租户可完全关闭外部模型；关闭后不得以故障回退名义绕过。

### 5. 结构化输出与结果验证

所有厂商输出统一经过：

- Schema 和字段白名单校验。
- 总分、评分点分值和满分边界校验。
- Rubric 点完整分类和未知评分点拒绝。
- 证据必须来自答案文本或批准的题块坐标。
- OCR 风险、提示注入、证据不足和多义性规则。
- 模型/提示词/Rubric/契约/能力版本一致性校验。
- 最多一次受控修复；再次失败后进入人工队列。

模型自报 confidence 不能直接决定自动通过。风险策略必须结合模型分歧、OCR、证据验证、冻结集校准和人工抽样结果。

### 6. 影子评测与题型级批准

评测单元是：

`deployment + model version + prompt version + rubric version + subject + grade level + question type`

每次 promotion 必须绑定：

- 授权、脱敏、冻结的评测集版本。
- 专家教师真值和仲裁规则。
- 教师直接接受率、改分率和平均改分幅度。
- 严重错误、false-zero、证据错误和公平性切片。
- 重复评分稳定性。
- P50/P95 时延、失败率和单位成本。
- 已批准适用范围、抽样复核率、过期时间和批准人。

模型、提示词、Rubric、厂商接口行为或关键参数变更后必须重新评测。撤销批准后，新任务立即停止使用该部署，历史结果保持可回放。

### 7. 成本、可靠性和审计

每次调用保存最小必要事实：

- tenant、exam、question、answer segment 的内部 opaque id。
- provider、deployment、模型版本、区域和原生 request id。
- prompt、Rubric、契约和路由策略版本。
- 输入/输出 hash、输入模态、尝试次数和回退链。
- 厂商用量、估算成本、耗时、错误和限流信息。
- 验证结果、风险标记、教师是否接受及最终修改原因。

预算耗尽、厂商不可用或结果无效时，默认进入人工队列。只有租户预先批准的策略才能尝试另一个厂商，且每次回退都必须入审计。

### 8. 产品界面

新增或扩展以下后台能力：

1. **供应商与部署**：配置原生 Adapter、Secret 引用、区域、能力、健康检查和停用。
2. **模型策略中心**：按学校/学科/题型设置外部授权、路由、预算、回退和抽样复核。
3. **模型评测中心**：冻结集运行、本地/多厂商并排比较、严重错误查看、promotion/revocation。
4. **模型运营看板**：调用量、费用、时延、失败、限流、回退、教师接受率和改分率。
5. **考试策略确认**：开考前显示本场考试将使用的模型、数据外发范围、预计成本和未批准题型。
6. **教师复核队列**：按模型分歧、OCR 风险、证据失败、评分标准外表达和临界分组织任务。

教师配置 Rubric，不直接维护复杂提示词；提示词由平台版本化管理。

## Competitive-data loop

教师修改 AI 建议时至少记录：

- AI 原建议、评分点和证据。
- 教师最终评分和修改原因。
- 受影响的 Rubric 点。
- 是否属于新增等价表达、OCR 错误、证据错误、模型漏判、模型误判或评分标准缺口。
- 当时的 provider/model/prompt/Rubric/evaluation 版本。

系统可聚合相同表达并向教研负责人建议：

`发现同类答案 -> 查看教师历史裁定 -> 确认等价表达 -> 发布新 Rubric 版本 -> 影子重评`

未经单独授权，这些数据只能用于产品内质量评估、规则和 Rubric 改进，不得直接用于供应商训练或模型微调。

## Acceptance criteria

### Governance and security

1. 外部模型默认关闭；租户关闭外部调用后，任何路由和故障回退都不能外发。
2. 浏览器、业务 API 和审计响应不返回厂商密钥；数据库不保存可回显明文密钥。
3. 外部请求字段白名单测试证明不包含学生身份、学校身份、历史成绩和最终成绩。
4. 图片调用只能发送与当前题关联的裁剪资源；整卷和跨题资源被服务端拒绝。
5. 每次外部调用、失败、修复、路由和回退均有可查询审计。

### Contract and reliability

6. 同一内部请求可以路由到本地和至少三个原生厂商 Adapter，业务模块无需厂商分支。
7. 厂商异常、超时、限流、未知字段、分数不一致或证据无效时，不产生有效建议分。
8. 幂等重放不重复计费；冲突请求被拒绝；回退链有界且不形成循环。
9. Provider、模型、提示词、Rubric、契约和策略版本可以回放到一次具体建议。
10. 预算耗尽和全部部署不可用时，任务进入人工队列，最终成绩事实不受影响。

### Product and quality

11. 评测中心能够在同一冻结集上并排展示本地和多个厂商结果，至少包含教师接受率、严重错误、证据有效率、稳定性、P95 时延和成本。
12. 未 promotion 的部署只能影子运行；promotion/revocation 后的新任务路由立即生效。
13. 教师能查看并拒绝建议、填写修改原因，修改事实与原模型结果准确关联。
14. 考试负责人在启用策略前能看到外发范围、适用题型、抽样复核率和预计成本。
15. 任何宣布支持的题型均有冻结集报告和明确批准范围；不得使用“已接 API”代替效果验收。

### Engineering gates

16. Go、Python、Web 单元和契约测试通过；真实 PostgreSQL E2E 覆盖租户隔离、promotion、预算、回退和人工降级。
17. 每个首批厂商使用授权沙箱/测试账号完成原生协议联调；CI 使用明确标记的协议 fixture，不伪造真实模型效果。
18. 生产配置检查拒绝明文弱密钥、未声明区域、无价格/计量配置和无数据策略的外部部署。

## Product metrics

不能只统计“模型准确率”。策略中心至少持续统计：

- 教师直接接受率和修改率。
- 平均改分幅度及严重错误率。
- 证据有效率和 false-zero。
- 高风险样本进入人工复核的召回率。
- 同一答案重复评分差异。
- 人工平均处理时间及节省时间。
- 单题、单卷和单考试模型成本。
- 成功率、超时率、限流率、回退率和 P95 时延。
- 按学校、学科、年级、题型和模型版本的公平性切片。

具体质量阈值由教研负责人基于冻结集批准，不能由厂商宣传指标或模型自报置信度替代。

## Verification plan

- 契约：供应商无关请求/建议 Schema、厂商扩展白名单和版本兼容。
- Adapter：每个原生协议的鉴权、请求映射、响应映射、用量、限流和错误 fixture。
- 安全：身份字段拒绝、Secret 不回显、整卷外发拒绝、租户禁用不可绕过。
- 策略：题型批准、本地优先、混合升级、双模型、预算和显式回退。
- 质量：冻结集运行、重复评分、严重错误、证据和教师裁定关联。
- E2E：浏览器选择策略，影子运行多个部署，教师查看/拒绝建议，运营看板和审计可追溯。
- 故障演练：一个厂商超时、一个限流、本地不可用、预算耗尽和全部失败，均安全进入人工队列。

## Plan review

### Why this is the correct next product investment

- STORY-057～059 已完成“契约—服务—平台接入”的安全骨架，下一步缺口不是再写一个 Prompt，而是把单一本地候选升级为可评测、可路由、可关闭的模型治理产品。
- 单个第三方 API 很容易复制；多厂商题型级评测、Rubric 资产、教师裁定闭环、隐私策略和成本运营才会形成长期竞争力。
- 本地小模型受设备性能限制，外部强模型可以用于影子基准和疑难题增强；本地部署仍提供隐私、离线和成本确定性。二者必须作为可治理组合，而不是二选一。

### Corrections incorporated from product review

1. 拒绝“新增一个 API Key 和模型下拉框”的功能式方案，改为模型策略中心。
2. 拒绝业务代码直连厂商，保持 Go API -> grading-agent -> Provider Adapter 的单一治理边界。
3. 拒绝 OpenAI-compatible 作为外部多厂商协议，改为每个厂商原生 Adapter。
4. 拒绝一次接入大量厂商，采用“多厂商地基 + 首批 2 个文本/1 个多模态 + 逐个验收”。
5. 拒绝模型自报 confidence 直接决定成绩，采用冻结集校准、证据验证、模型分歧和人工策略。
6. 拒绝先微调，先积累可授权、可解释的教师裁定数据。

### Principal risks

- 原生 Adapter 增加维护成本；通过小接口、独立 fixture、能力矩阵和逐厂商验收控制。
- 厂商 API、模型版本和计费可能变化；部署版本固定，变化触发健康降级和重新评测。
- 多厂商可能导致成本失控；影子样本率、预算和有界回退必须在调用前生效。
- 供应商结构化输出能力不同；内部验证器是最终边界，不因厂商声称支持 Schema 而放宽。
- 教师反馈可能包含隐私或不一致裁定；反馈用途受授权约束，教研组仲裁后才能沉淀为 Rubric 资产。
