# STORY-076：考试运营中心

状态：Planned。优先级：P1。依赖：exam_session、可信 dashboard、processing、review、quality、arbitration 与 release gate。

## 问题与范围

多科考试需要一个能回答“哪里阻断、还剩多少、是否能按时结束”的运营视图。按现有 exam_session 聚合事实，不新建重复考试或评分实体。

- 首切片聚合各科采集、页面处理、客观题评分、主观题阅卷、仲裁与发布 Gate。每个指标声明单位、分母、采样时间和来源：页、答卷、题目、评分任务不能混算。
- 区分成功/失败/待处理/阻断/未知，核心来源不可用显示 unavailable，次要来源带 warnings；不能用 0 或 100% 替代失败读数。
- 阻断条目携带科目、严重度、负责人和受权下钻；现有异常、仲裁、门禁页面处理原事实，不从总控页旁路修正。
- 后续用近时窗完成任务数估算吞吐与区间 ETA，声明活跃阅卷员定义、时窗和数据新鲜度。样本不足、长时间暂停或速率不稳定时不显示精确结束时间。
- 多科状态变更复用已有命令与幂等，不因总控聚合写第二套完成状态。

## 非范围

不创建“联考模块”替代 exam_session，不重复聚合为新的成绩事实，不把未来排班或复杂预测模型纳入首版，不以预计结束代替发布门禁。

## 预计修改文件

拟扩展 `internal/dashboard/` 或新增薄 `internal/examoperations/` 查询服务；修改现有来源 adapters、管理端 session 运营页、OpenAPI/SDK。仅在有明确读取成本证据时增加带来源版本的缓存/投影。

## 测试方式与验收标准

Go 聚合测试覆盖多科、来源失败、零分母和不同单位；真实 PostgreSQL 核对超过展示页数的全量范围与状态；UI 验证下钻和未知状态。ETA 用确定性时间夹具验证区间/无数据语义，实际估时准确率另留学校数据。

验收要求汇总等于授权来源全量事实，不按展示列表推总数；已发布与未通过 Gate 分开；来源失败显式可见；ETA 显示依据；用户只能进入本人获授权科目。首版进度与阻断验收后才进入 ETA 切片。
