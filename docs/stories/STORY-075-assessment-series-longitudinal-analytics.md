# STORY-075：跨考试纵向学情

状态：Planned。优先级：P1。依赖：不可变 Score Release；069C 的受控知识点增强可比性。

## 问题与范围

现有报告以单考试为中心。增加 assessment_series 与成员考试，展示学生在同学科同学段的正式发布趋势和知识点表现，并明确发布修订与试卷差异。

- 系列定义学校、学年、学段/年级、学科、排序与覆盖范围；学生身份复用内部 UUID 与授权组织数据，不按姓名匹配。
- 每个趋势点记录 exam、release_id/version、published_at、当前正式值、历史发布值、原始分/满分、得分率、有效样本与缺考/缺失状态。
- 新 release 替换“当前趋势”引用并保留修订标记，历史视图按显式 release 集合重现；不查询可变 final_grade 当历史值。
- 知识点映射用版本化 taxonomy；多知识点归属和分值分配口径可见。题目数量、满分与覆盖变化显示可比性提示；无共同量尺时不把涨分解释为真实能力提升。
- 教师看到下降区间与证据下钻；学生只见本人已公开事实。聚合按组织权限过滤，缓存键包含 release 集合、taxonomy/mapping 版本与授权范围。

## 非范围

不宣称潜在知识掌握概率、不训练 BKT/DKT/AKT、不自动等值化不同难度考试、不把得分率写成真实能力参数、不修改发布事实。

## 预计修改文件

拟新增 `internal/assessmentseries/`、系列/成员/分析投影迁移、管理端系列页和学生端趋势组件、`docs/api/assessment-series.md`；修改 Score Release 查询适配、OpenAPI/SDK 与缓存失效入口。

## 测试方式与验收标准

Go/真实 PostgreSQL 验证 v1→申诉→v2 的当前与历史读数、跨学科拒绝、缺考与缺失、不等满分、taxonomy 切换和范围过滤。UI 验证趋势点修订标记、覆盖信息和版本下钻；软件证据与教师解释效果分开。

验收要求原发布值不会静默改写，未发布/不可见考试不入学生趋势；知识点覆盖不足显示原因，低可比性不生成能力结论；缓存不会跨权限或 release 泄露。首次切片只做系列与总分/得分率趋势，再验收知识点纵向投影。

## 规划审阅与实施记录

规划已限定为 Longitudinal Performance Analytics 并固定发布版本来源。当前实现、实现审阅、修正与审批待留证；知识追踪需未来专项数据研究。
