# STORY-065：真实角色工作区与访问边界

状态：Implemented（首个生产切片）

## 问题

旧前端只有“管理端/阅卷端”两个体验，教师、阅卷老师和仲裁员共用菜单语义；菜单隐藏、页面路由和后端权限容易出现不一致。

## 工作区

| 工作区 | 主要职责 | 默认可见能力 |
| --- | --- | --- |
| 平台管理员 | 管学校和平台服务 | 学校、系统状态、模型治理、审计 |
| 学校管理员 | 管学校考试全流程 | 考试、答题卡、阅卷、成绩、组织 |
| 考试负责人 | 推进获授权考试 | 考试配置、采集、阅卷、结果 |
| 教师 | 处理本人教学任务 | 本人考试、报告和反馈 |
| 阅卷老师 | 匿名评阅分配任务 | 我的阅卷 |
| 仲裁员 | 处理分配的评分差异 | 我的仲裁 |

同一账号可同时拥有教师、阅卷和仲裁职责；前端按其全部工作区判断路由，不因首个角色丢失其他授权。

## 一致性规则

- 侧边栏、直达 URL 和页面渲染共用工作区注册表及权限判断。
- 后端 RBAC 仍是最终授权边界，前端隐藏不代替后端校验。
- 平台管理员排除学校考试路由；阅卷老师不能通过直达管理端 URL 进入考试管理。

## 非范围

- 不为测试创建大量伪身份；生产验证每种真实角色保留一个代表账号即可。
- 不新增后端角色名，不复制已有权限系统。
- 不把“批次、租约、适配器”等内部概念放入普通教师一级导航。

## 验收证据

- Playwright 验证平台管理员直达学校考试管理得到无权限。
- Playwright 验证阅卷老师只能看到自己的阅卷工作区。
- 生产路由门禁和 TypeScript 类型检查必须通过。
