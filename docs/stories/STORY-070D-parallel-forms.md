# STORY-070D：平行卷与重叠控制

状态：Planned（后续阶段）。优先级：P1。父 Story：[070](STORY-070-assessment-blueprint-smart-assembly.md)。依赖：070C。

## 问题与范围

为补考、AB 卷和不同考场生成多份符合相同蓝图的候选，控制逻辑 Item/family 重叠，同时清楚区分规格接近与真实测量等值。

- form_count、共同锚题、跨卷 Item/family overlap 上限、总分/题量/覆盖/标签或观测难度差异容差均为版本化约束。
- 先联合规划跨卷题目分配，再逐卷完整校验；不能简单重复单卷 solver 后宣称多卷约束满足。
- 展示每卷全部硬约束、跨卷重叠矩阵、难度来源、覆盖差异与统计充分性；无 IRT 校准时不显示测量信息量或等值结论。
- 教师一次确认多卷时预留/消费曝光按组处理，明确全组原子创建或有耐久恢复的分步语义；已有考试不能在部分失败后假装整组完成。
- 共享锚题作为明确例外记录，题号/顺序与答题卡仍分别进入每个目标考试配置。

## 非范围

不自动等值化、IRT 校准或跨校成绩换算，不把难度标签相似写成测量等价，不把此切片作为第一阶段 070C 的前置。

## 预计修改文件

扩展 `internal/testassembly/` form set/joint constraints 与迁移，questionbank 组曝光预留、管理端跨卷比较/确认、OpenAPI/SDK。必要时可使用 070E 后端，但初版接口不强依赖外部 Worker。

## 测试方式与验收标准

Go 小题池 oracle 验证逐卷与跨卷约束；真实 PostgreSQL 验证组预留、部分失败恢复与重放；UI 验证 overlap 矩阵与校准缺失。

验收要求每卷满足全部 hard constraints，Item 版本变化不能绕过 logical overlap；共同锚题有理由；跨卷差异可核算；确认/重试不重复题目或额度。真实测量可比性需独立校准数据与评审，不随软件批准宣称成立。

规划已区分多卷联合约束与心理测量等值。实现、实现审阅、修正和 Approval 待证据；第一阶段不运行本切片。
