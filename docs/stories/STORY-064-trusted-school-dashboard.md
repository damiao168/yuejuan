# STORY-064：学校工作台可信聚合

状态：Implemented

## 问题

旧工作台先截取少量考试，再由前端逐场请求答题卡并推算总数。考试超过展示上限时，首页数字会少算；“答题卡、题目、评分差异、考试”也容易混用单位。

## 范围

- 新增 `GET /api/v1/dashboard/summary`，在服务端按当前租户和学校范围汇总全部考试。
- 分开返回进行中考试、采集中考试、待阅题目、涉及答题卡、待仲裁差异、涉及答题卡、失败/未匹配/质量异常答题卡和待发布考试。
- 返回阻断事项、下钻地址、进行中考试和最近业务审计；单个次要来源失败时返回 `warnings`，核心考试或答题卡来源失败时返回稳定 503。
- 前端首页只消费聚合结果，不再用展示列表推算总数。

## 权限与失败语义

- 学校管理员和考试负责人复用 `exam:manage` 边界。
- 平台管理员不能读取单校业务聚合，返回 403。
- 聚合不可用返回 `dashboard_summary_unavailable`；不得用 0 冒充未知数据。

## 非范围

- 不新增统计快照表，不改成绩事实。
- 不把模型治理或系统运维指标混入学校工作台。
- 首页最多展示五场考试仅是展示限制，不影响聚合口径。

## 验收证据

- 单元测试覆盖 12 场考试和跨租户隔离，证明统计不受前端展示上限影响。
- PostgreSQL E2E 覆盖 11 场考试、租户范围和平台管理员拒绝。
- 首页明确显示“6 份答题卡包含 107 道待阅题目”等单位关系。
