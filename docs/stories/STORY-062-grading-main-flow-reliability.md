# STORY-062 阅卷主链可靠性与教师连续阅卷

## Status

Software Accepted（2026-08-01；真实打印/扫描仍由 STORY-060 `V-060P` 跟踪，不标记 Production Ready）

## Product decision

本 Story 只解决学校试点最先会遇到的阅卷主链问题：

> 管理员能够在数据完整时可靠启动评分、在数据不完整时得到可执行的阻塞原因；阅卷教师能够连续处理任务，不因重复加载和状态竞争频繁中断。

本 Story 不扩张模型厂商数量，不把主观题 AI 建议当作最终成绩，也不以合成数据替代打印、扫描、OCR 和教师真值验证。

## Scope

1. 启动评分前检查考试状态、题目、题块、裁剪影像、模板坐标和未结束评分任务。
2. 评分启动失败返回结构化原因，前端直接展示阻塞项和预计自动/人工数量。
3. 同一考试的评分启动保持事务串行和幂等，禁止并行创建重复任务。
4. 管理员监控每张匿名答题卡的处理进度、题块状态、识别结果、得分和失败原因。
5. 整卷视图保留每题红色小分标记与总分汇总，AI 建议必须有明显来源区别。
6. 教师“提交并下一份”预取下一任务工作区和题块影像；选择任务时重新核验任务状态和归属，草稿始终读取最新版本。
7. 为关键门禁补 PostgreSQL E2E，并补管理员启动评分、整卷监控、教师提交下一份的浏览器回归。

## Non-scope

- STORY-061C3 模型晋级、生产路由、熔断和真实外部厂商数据外发。
- 主观题评分 Agent 的批量编排；该能力进入 STORY-063。
- 打印机、扫描仪和真实纸张闭环；该证据属于 `V-060P` 外部验证轨。
- 真实 OCR 准确率和双教师 Gold 评分效果宣称；分别属于 `V-OCR` 和 `V-GOLD`。
- 高可用、多校大规模部署、学生端和成绩发布版本化。

## Existing capability reused

- STORY-056 的评分运行、OMR Worker、失败重试、取消和单题重处理。
- `ScoringPaperMonitor` 的匿名答题卡分组、整卷页面和红色题分覆盖层。
- 人工复核任务租约、草稿修订、离线草稿兜底和提交门禁。
- STORY-060 的花名册、缺考语义、答卷完整性和发布质量门禁。

## Acceptance criteria

1. 不满足启动条件时，管理员看到具体阻塞项，不再收到泛化 `grading_operation_failed`。
2. 就绪度检查与创建评分任务位于同一事务保护范围，两个并发请求最多创建一个有效运行。
3. 100 题块 PostgreSQL 验收流程能覆盖阻断、放行、取消恢复和活动任务冲突。
4. 教师提交后优先展示已预取的下一份；缓存陈旧或失败时不影响正确加载。
5. 预取不读取他人任务草稿、不提前续租、不改变任务状态。
6. Go 测试、Web 类型检查、生产构建和生产路由检查通过。
7. 未完成真实数据库、浏览器或物理验证时，文档不得标记 Approved。

## Plan review

- 与当前仓库重叠能力已明确复用，没有重建整卷监控、评分引擎、人工复核或答卷完整性模块。
- 自动评分仍是管理员运营能力；教师只处理人工复核与 AI 建议，不暴露批量模型运行控制。
- 自动批处理由 Worker 并发完成，不设计强制逐张自动跳转；管理员可以查看进度并自主选择答题卡。
- 本 Story 的剩余工作由真实运行证据决定，不继续用页面数量或模型治理对象数量代替产品推进。
