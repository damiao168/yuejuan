# STORY-071：题目质量与曝光治理

状态：Planned。优先级：P0。依赖：069F、070C。

## 问题与范围

教师需要知道题目为什么应复查、统计是否充分、题池是否过度使用。基于版本级发布统计与实际 usage 生成可解释质量信号，并提供人工处置记录。

- 首切片：样本不足、负区分度、连续异常、选项响应缺失/无效和高频使用的规则集；每个信号记录规则版本、阈值、样本 N、来源 release、计算时间与原因。
- 后续切片：申诉率、重评改分率、群体/时间稳定性、题池覆盖与利用率。申诉与重评的事件分子、有效响应分母、时间窗分别定义；未知来源显示 unavailable。
- 流程为 needs_checking → 人工检查 → 保留/新版本/退役。只标记，不自动删题。严重信号能否阻断选题由显式 policy 决定，单次信号不静默改变 Item 状态。
- 质量中心逐版本展示；logical Item 显示版本概览。旧版结果不作为新版校准事实。

## 非范围

不生成无解释的“健康分 87”，不对小样本估计 IRT，不自动惩罚作者或删除低区分度题目，不新建评分事实。

## 预计修改文件

拟扩展 `internal/questionbank/` 的规则投影与审核记录，新增质量规则/信号迁移、`apps/web-admin/src/features/question-bank/quality/`，修改 OpenAPI、生成 SDK 与统计任务入口；通知由 072 接入。

## 测试方式与验收标准

Go 规则测试覆盖阈值边界、样本不足和连续异常；PostgreSQL 验证重放、规则版本切换及处置审计；Web 验证理由、N 与下钻来源显示。

验收要求同一数据/规则版本生成相同信号；未知数据不记零；新版不继承旧版信号；人工处理可追溯；预警不会自动删题；策略阻断和允许例外都有证据。学校阈值与真实题目质量效果需另留外部评审证据。
