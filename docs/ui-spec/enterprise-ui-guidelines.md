# EduGrade Enterprise UI 设计规范

## 1. 设计原则

EduGrade Enterprise 是长时间使用的教育评测工作系统，不做营销式界面，不用装饰掩盖业务状态。

### 专业

- 所有页面先呈现工作对象、状态和可执行操作，再呈现解释。
- 涉及成绩、审计、申诉、改分、AI 建议时必须显示来源、时间、权限或水印提示。
- 不使用夸张插画、口号式标题、过度渐变或娱乐化动效。

### 高效

- 高频操作在首屏可见：筛选、刷新、保存、提交、导出、重试。
- 表格页必须支持搜索、筛选、分页/滚动、空状态和错误恢复。
- 阅卷工作台操作路径不得超过：选任务 -> 看证据 -> 评分 -> 保存/提交。

### 克制

- 页面背景使用 `#F5F7FA`，主工作区使用 `#FFFFFF`。
- 卡片只用于独立工具、列表项、重复条目、详情抽屉和弹窗。
- 不把整页切成大量装饰卡片；业务区域优先使用布局、分隔线和表格。

### 高信息密度

- 后台和 EXE 使用紧凑字号、稳定行高和可扫描标签。
- 关键指标用 4-8 个以内的紧凑指标块，不做大号营销 KPI。
- 表格默认中密度，长文本用省略、tooltip 或详情抽屉承接。

### 强状态反馈

- 所有异步操作必须有 loading。
- 所有失败必须给出失败原因和下一步动作。
- 高风险操作必须二次确认：发布成绩、改分、导出审计、提交离线草稿、关闭申诉。

### 长时间使用不疲劳

- 主色只用于主操作、选中态、链接和重要进度。
- 大面积背景不得使用高饱和色。
- 同一屏内最多一个主要行动按钮，其余使用默认、危险或文本按钮。
- 阅读型区域行高不低于 `1.5`，评分表单不低于 `1.45`。

## 2. 颜色规范与视觉 Token

| Token | 值 | 用途 |
| --- | --- | --- |
| `primary` | `#1677FF` | 主操作、链接、当前导航、进度主色 |
| `success` | `#52C41A` | 成功、通过、已发布、已同步 |
| `warning` | `#FAAD14` | 待复核、待接入、冲突、风险 |
| `error` | `#FF4D4F` | 失败、驳回、危险操作、不可提交 |
| `info` | `#13C2C2` | 信息提示、诊断、辅助状态 |
| `background` | `#F5F7FA` | 页面背景 |
| `card` | `#FFFFFF` | 面板、工具、表格容器 |
| `text-primary` | `#1F2329` | 标题、正文主文字 |
| `text-secondary` | `#646A73` | 辅助说明、时间、弱标签 |
| `border` | `#E5E6EB` | 边框、分隔线、表格线 |

扩展灰阶：

- `text-weak`: `#8F959E`
- `surface-soft`: `#F9FAFC`
- `shadow`: `0 12px 32px rgba(31, 35, 41, 0.08)`
- `radius`: `6px`

## 3. 字体规范

- 字体栈：`Inter, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`。
- 不使用负 letter-spacing；`letter-spacing` 默认 `0`。
- 不使用随 viewport 宽度缩放的字体。
- 中文界面不使用过轻字重；正文默认 `400`，关键标签 `600`。

| 场景 | 字号 | 行高 | 字重 |
| --- | --- | --- | --- |
| 页面标题 | `24-28px` | `1.2` | `700` |
| 区块标题 | `16-18px` | `1.3` | `600` |
| 表格正文 | `13-14px` | `1.45` | `400` |
| 表单标签 | `13-14px` | `1.4` | `500` |
| 辅助说明 | `12-13px` | `1.5` | `400` |
| 状态标签 | `12px` | `20-24px` | `500` |

## 4. 间距规范

使用 4px 基础网格。

| Token | 值 | 用途 |
| --- | --- | --- |
| `space-1` | `4px` | 图标与文字间距、标签内部微调 |
| `space-2` | `8px` | 按钮组、小表单间距 |
| `space-3` | `12px` | 列表行、工具条间距 |
| `space-4` | `16px` | 面板内区块 |
| `space-5` | `20px` | 页面主区块 |
| `space-6` | `24px` | 页面外边距、布局 gutter |
| `space-8` | `32px` | 大区块间距 |

规则：

- 后台主内容左右 padding 桌面为 `24px`，移动为 `16px`。
- 面板 padding 桌面为 `18-20px`，移动为 `14-16px`。
- 表格工具栏与表格之间保持 `12-16px`。
- 不使用超过 `32px` 的装饰性空白。

## 5. 产品布局

### Web 管理后台

布局结构：

```text
左侧导航 244px
顶部上下文栏 64-72px
主工作区 minmax(0, 1fr)
详情抽屉 420-560px
```

要求：

- 左侧导航承载主模块，不在顶部横向堆菜单。
- 顶部栏展示租户、当前用户、当前任务/考试、刷新或导出状态。
- 页面首屏必须出现当前模块的真实工作对象。
- 真实 API 页面缺 token 时必须显示错误状态，不回退 mock。

### 阅卷工作台

桌面优先三栏布局：

```text
顶部：考试 / 任务 / 题号 / 保存状态 / 提交入口
左侧：答卷查看器 42-50%
中间：OCR / AI 证据 / 低置信提示 24-30%
右侧：Rubric / 分数 / 评语 / 提交 26-32%
底部：快捷操作 / 争议 / 返回重评
```

要求：

- 答卷图像和评分面板必须同屏可见。
- 保存状态必须持续可见：未保存、保存中、已保存、同步失败。
- AI 建议不得遮挡人工评分。
- 移动/窄屏降级为 tabs：答卷、证据、评分。

### Windows EXE

布局结构：

```text
左侧工作区导航 248px
顶部状态条 72px
主工作区：连接登录 / 任务 / 扫描 / 离线阅卷 / 同步 / 诊断 / 日志
```

要求：

- EXE 首屏是工作站，不是欢迎页。
- 网络状态、登录状态、本地安全存储状态必须可见。
- 未实现原生能力必须显示“未配置/待接入”。
- 扫描与离线阅卷必须保留本地日志入口。

- 路由权限不足时显示无权限页，不静默跳转。

## 7. 页面状态规范

### Loading

- 表格 loading 使用骨架或表格内 spinner，不全屏遮罩。
- 首次加载复杂详情可使用局部 `LoadingState`。
- 超过 5 秒应显示“仍在读取真实 API”提示。

### Empty

空状态必须包含：

- 空的对象。
- 可能原因。
- 下一步动作。

示例：`暂无真实任务。请确认已登录、具备 review:manage 权限，并刷新任务列表。`

### Error

错误状态必须包含：

- 后端错误 message 或 code。
- 是否因 token、权限、网络、参数导致。
- 可操作按钮：重试、返回、重新登录。

### Success

- 成功 toast 只用于短操作。
- 高风险成功必须在页面状态中留痕，例如发布状态、导出水印、同步结果。

### Warning

用于：

- 未配置/待接入。
- 数据不完整。
- AI 低置信。
- 冲突、待复核。
- 本地缓存不安全或离线状态。

## 8. 表格规范

默认：

- 行高：`44-52px`。
- 表头固定在长表格中启用。
- 操作列固定右侧，宽度 `120-180px`。
- ID/时间/状态使用等宽或紧凑显示。

必须支持：

- 搜索或筛选。
- loading、empty、error。
- 分页或虚拟滚动。
- 关键操作二次确认。

禁止：

- 表格中填假数据示例。
- 用彩色标签替代具体状态说明。
- 把长 JSON 直接塞进单元格；用抽屉展示。

## 9. 表单规范

表单布局：

- 搜索筛选使用横向紧凑布局。
- 创建/编辑使用垂直表单。
- 高风险提交在按钮附近显示影响范围。

校验：

- 必填项必须前端校验。
- 后端错误必须显示在表单顶部或对应字段。
- 数字输入使用 `InputNumber`，不得用普通文本框。

提交：

- 提交中禁用主按钮。
- 成功后刷新真实数据。
- 失败不清空用户输入。

## 10. 按钮规范

按钮类型：

- Primary：当前页面唯一主操作。
- Default：次要操作。
- Danger：删除、关闭申诉、覆盖、清空缓存。
- Text/Icon：刷新、查看、展开、复制。

图标：

- 工具按钮优先使用 lucide 图标。
- 常见动作只用图标或图标+文字：刷新、上传、下载、保存、提交、导出、重试。
- 不用自绘 SVG 替代已有图标库图标。

高风险按钮：

- 必须二次确认。
- 确认文案必须包含对象名称和影响。

## 11. 标签与状态色规范

| 状态 | 颜色 | 用途 |
| --- | --- | --- |
| `success` | `#52C41A` | passed、published、synced、approved |
| `warning` | `#FAAD14` | pending、conflict、not_configured、needs_review |
| `error` | `#FF4D4F` | failed、rejected、invalid、offline error |
| `info` | `#13C2C2` | diagnostic、processing info |
| `primary` | `#1677FF` | selected、active、uploading、syncing |

标签文案必须使用业务词，不只显示颜色。

## 12. 阅卷工作台布局规范

任务列表：

- 默认展示当前教师可处理任务。
- 筛选：可处理、待分配、已分配、处理中、退回、已提交。
- 列：匿名号、题号、来源、状态、优先级、创建时间。

工作台：

- 答卷查看器支持缩放、旋转、重置。
- OCR 文本与 AI 建议必须可复制或引用。
- Rubric 面板必须显示总分、已选分、剩余分。
- 提交前必须校验分数范围。

保存：

- 在线保存显示“保存中/已保存/失败”。
- 离线保存显示“加密保存/待同步/同步失败/冲突/已同步”。

## 13. 答卷查看器规范

必须支持：

- 图片/PDF 预览。
- 缩放。
- 旋转。
- 适配宽度。
- 加载失败状态。

答题区域：

- 已知 bbox 时用边框或半透明高亮。
- 高亮不得遮挡答案主体。
- 无 bbox 时显示“未配置答题区域”。

禁止：

- 模糊、裁切、暗化导致答案不可读。
- 用占位图片冒充真实答卷。

## 14. AI 证据展示规范

AI 证据必须包含：

- 建议分。
- 置信度。
- 命中点。
- 缺失点。
- 风险标记。
- 模型/规则版本。
- 是否 mock。

展示规则：

- `mock=true` 必须显示 mock 标签。
- 低置信度使用 warning，不使用 success。
- AI 建议不得自动覆盖人工分。
- 原始输出放折叠面板，不占主视图。

## 15. Rubric 评分面板规范

Rubric 面板必须包含：

- 题目满分。
- Rubric 版本。
- 每个 point 的描述、分值、是否必选。
- 当前已选分。
- 最终分。

交互：

- point 分值用数字输入或步进器。
- 必选 point 未处理时显示 warning。
- Rubric 总分与题目满分不一致时阻止提交。

## 16. 快捷键规范

阅卷工作台建议：

| 快捷键 | 动作 |
| --- | --- |
| `Ctrl+S` | 保存草稿 |
| `Ctrl+Enter` | 提交评分 |
| `N` | 下一题/下一任务 |
| `P` | 上一题/上一任务 |
| `+` | 放大 |
| `-` | 缩小 |
| `0` | 重置视图 |
| `R` | 标记复核/争议 |

要求：

- 快捷键必须可发现，放在底部或帮助弹窗。
- 输入框聚焦时不得触发全局快捷键。

## 17. 成绩报告页面规范

页面结构：

1. 考试选择与刷新。
2. 核心统计。
3. 分数分布。
4. 班级对比。
5. 题目分析。
6. 知识点与高频错误。
7. 阅卷质量。
8. 导出状态。

规则：

- 图表只展示真实后端数据。
- `available=false` 或无数据时显示空状态，不补假曲线。
- 导出必须显示水印和审计提示。

## 18. 申诉页面规范

页面结构：

- 申诉列表。
- 申诉详情。
- 原评分证据。
- 历史改分。
- 审计记录。
- 处理表单。

规则：

- 改分必须二次确认。
- 调整分数必须显示原分、新分、原因。
- 无审计权限时显示无权限，不伪造审计。
- 学生可见结果和内部备注必须分开。

## 19. 审计页面规范

页面结构：

- 筛选区。
- 审计表格。
- 详情抽屉。
- 导出确认。
- 租户隔离说明。

规则：

- 不提供编辑或删除入口。
- before/after JSON 使用格式化视图。
- token、password、authorization、secret、credential 必须脱敏。
- 导出前提示水印和审计留痕。

## 20. EXE 客户端规范

### 扫描工作站

- 选择考试和 submission 后才能选择文件。
- 文件入队前做本地质量检查。
- 队列状态必须是 `pending/uploading/succeeded/failed`。
- 离线时不上传，联网后继续当前会话可上传项。
- 刷新后恢复队列元数据，文件句柄不可恢复时提示重新选择。

### 离线阅卷

- 下载任务包必须来自真实 API。
- 草稿必须加密保存或经过安全存储抽象。
- 同步前必须做冲突检测。
- 同步结果必须可见并可重试。
- 不把本地日志当作后端审计。

### 诊断

- 显示运行时、版本、日志路径、网络状态。
- 未接入 Stronghold/SQLite/自动更新时显示“未配置/待接入”。

## 21. 可访问性要求

- 所有按钮必须有文本或 tooltip。
- 表单字段必须有 label。
- 状态不能只靠颜色表达，必须有文字。
- 交互目标最小高度 `32px`，移动端建议 `40px`。
- 错误信息必须出现在屏幕阅读器可读区域。
- 图表必须有表格或文字摘要。

## 22. 响应式要求

断点：

- `>=1200px`：桌面完整布局。
- `980-1199px`：双栏降级。
- `<980px`：侧栏改为顶部/单列，工作台改 tabs。
- `<560px`：按钮换行，表格内部横向滚动，整页不得横向滚动。

规则：

- 页面级 `scrollWidth` 不得大于 viewport width。
- 表格允许内部横向滚动。
- 固定工具栏不得遮挡内容。
- 移动端不显示大面积空白 hero。

## 23. 禁止事项

- 禁止用 mock/stub 冒充真实能力。
- 禁止把未实现能力写成可用。
- 禁止创建营销式首页代替工作台。
- 禁止用花哨 AI 聊天界面代替阅卷流程。
- 禁止隐藏低置信度、冲突、权限不足和未配置状态。
- 禁止无二次确认执行发布、改分、导出审计、清空缓存。
- 禁止使用一整页同色系装饰。
- 禁止卡片套卡片。
- 禁止页面级横向滚动。
- 禁止按钮文字溢出。

## 24. 前端验收清单

每个新增页面交付前必须检查：

- 是否显示真实数据边界。
- 缺 token 是否明确错误。
- 无权限是否明确提示。
- loading/empty/error/success/warning 是否完整。
- 是否有整页横向滚动。
- 是否有控制台 error/warning。
- 是否存在未标注的 mock。
- 高风险操作是否二次确认。
- 颜色、字号、间距是否符合 token。
- 移动端文字是否溢出。
