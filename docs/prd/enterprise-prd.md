# EduGrade Enterprise 企业级 PRD

## 1. 产品背景

学校、教培机构、考试机构和企业培训部门在阅卷场景中同时面对四类问题：

- 纸笔答卷采集、OCR、题目切分和人工校正链路长，错误难追踪。
- 主观题阅卷存在重复判断、标准不一致、双评分差和仲裁成本。
- 成绩发布、申诉、改分、导出和报告缺少完整审计闭环。
- AI 能提升效率，但如果直接替代教师终审，会带来公平、合规和信任风险。

EduGrade Enterprise 的产品目标不是“AI 自动批改软件”，而是可私有化部署、可审计、可人工复核、可双评仲裁、可申诉的智能评测基础设施。

## 2. 产品定位

EduGrade Enterprise 是企业级多智能体智能阅卷与学情诊断平台，覆盖考试创建、试卷配置、答卷采集、OCR、答案切分、AI 辅助阅卷、人工复核、双评仲裁、成绩发布、申诉处理、学情报告、考试质量分析、权限审计和私有化部署。

## 3. 目标客户

### 3.1 学校

适用于中小学、职业学校、高校院系的日常作业、月考、期中期末、联考和模拟考试。

核心诉求：

- 降低教师重复阅卷负担。
- 提升主观题阅卷一致性。
- 支持年级、班级、学科质量分析。
- 支持校内私有化与数据不出校。

### 3.2 教培机构

适用于大规模测评、诊断、模考、分层教学和课后反馈。

核心诉求：

- 多校区、多班级统一阅卷。
- 快速生成学情诊断和教学建议。
- 支持教师协同、质量抽检和申诉处理。

### 3.3 考试机构

适用于高风险正式考试、竞赛、等级测评和能力认证。

核心诉求：

- 盲评、双评、仲裁和审计闭环。
- 成绩发布前质量检查。
- 全流程留痕、导出审批、数据归档。

### 3.4 企业培训部门

适用于内部认证、合规考试、培训测评和岗位能力评估。

核心诉求：

- 统一考试和培训评估。
- 支持客观题自动评分与主观题人工复核。
- 支持组织维度报告和合规审计。

## 5. 核心业务流程

### 5.1 创建考试

学校管理员、年级主任或教师创建考试/作业，配置考试名称、类型、学科、总分、适用班级、阅卷模式、申诉策略和发布策略。

状态从 `draft` 开始。发布后的关键配置不得随意修改。

### 5.2 上传试卷

用户上传 PDF、Word、图片或答题卡模板。系统保存文件元数据和版本，不直接把文件存入数据库。

### 5.3 配置题目

题目配置包括题号、题型、分值、知识点、答题区域、标准答案和评分方式。系统必须能校验总题目分值是否等于考试总分。

### 5.4 配置评分标准

主观题必须配置 Rubric、采分点、扣分点、等价答案、样例答案和版本。Rubric 修改必须产生新版本，正式考试的 Rubric 需要审批或锁定。

### 5.5 上传答卷

答卷来源包括扫描仪、PDF、图片、手机拍照、在线作答和第三方系统。每份答卷生成 submission，并支持多页、缺页、重页、模糊、条码失败等质量标记。

### 5.6 OCR

OCR 任务输出文本、坐标、置信度、页 ID、引擎名称和版本。低置信度 OCR 不得直接进入自动评分，必须触发人工校正或复核。

### 5.7 答题区域切分

系统根据题目答题区域或版面解析结果生成 answer_segment。切分失败或缺少坐标时返回明确错误，并进入人工处理。

### 5.8 AI 初评

AI 对客观题、填空题、简答题、计算题、作文题等生成建议分。所有 AI 结果必须包含证据、置信度、采分点、扣分原因、风险标记、模型版本、Prompt 版本和 Rubric 版本。

### 5.9 证据校验

证据校验检查 AI 的每个得分点是否能对应到原图、OCR 文本或答题区域。缺少证据的建议分不得直接进入终审。

### 5.10 人工复核

教师或阅卷员在工作台查看原图、OCR、AI 建议、Rubric 和同类答案，提交人工分、评语、批注和复核结果。改分必须记录原因。

### 5.11 双评仲裁

正式考试和高风险主观题支持双评、盲评和仲裁。分差低于阈值时按策略取平均或规则值；分差超过阈值时进入仲裁任务。

### 5.12 成绩确认

成绩确认前必须完成质量检查：未完成阅卷、未完成仲裁、OCR 失败、异常分数、缺失最终分、Rubric 未锁定等问题必须阻止发布。

### 5.13 成绩发布

成绩发布需要审批。发布后关键成绩记录锁定，任何调整必须通过申诉、复核或管理员授权流程，并写审计日志。

### 5.14 学生反馈

学生查看总分、题目得分、教师反馈、可见批注和申诉入口。是否展示排名、AI 反馈、知识点建议由学校策略控制。

### 5.15 申诉处理

学生提交申诉后，教师、学科组长或管理员按权限处理。申诉处理可接受、驳回、要求补充或调整分数。所有处理说明和改分必须留痕。

### 5.16 学情报告

系统生成学生、教师、年级和管理者报告，包括分数分布、知识点掌握、错因分析、题目质量、阅卷质量和教学建议。

### 5.17 归档审计

考试结束后进入归档状态。答卷、成绩、Rubric、AI 输出、人工分、最终分、申诉和审计日志按保留策略归档。

## 6. 题型支持

| 题型 | 评分方式 |
| --- | --- |
| 单选 | 标准答案自动判分 |
| 多选 | 标准答案、部分分、错选扣分 |
| 判断 | 标准答案自动判分 |
| 填空 | 标准答案、同义答案、容差、人工复核 |
| 数值 | 数值容差、单位换算、有效数字 |
| 公式 | 公式识别、等价判断、人工确认 |
| 简答 | Rubric + AI 建议 + 人工确认 |
| 计算 | 步骤采分 + 公式/数值校验 + 人工确认 |
| 作文 | 多维 Rubric + AI 建议 + 双评/人工确认 |
| 论述 | Rubric + 双评/仲裁 |
| 编程题，可选 | 单元测试、静态分析、人工复核 |

## 7. AI 使用边界

- AI 只能给建议分，不能作为高风险考试的唯一评分者。
- AI 不能绕过 Rubric、评分策略、人工确认、复核、仲裁和审计。
- AI 结果必须包含分数、置信度、证据、采分点、扣分原因、风险标记、版本信息和人工复核建议。
- 低置信度必须进入人工复核。
- 缺少证据、证据不一致或输出结构不合法时，AI 结果必须作废或进入人工处理。
- 学生答案不得通过 Prompt 注入改变系统评分规则。
- 学生数据不默认用于模型训练。
- 外部模型调用必须可关闭，私有化模型和本地模型必须可接入。
- mock/stub 结果必须显式标记，不能冒充真实模型能力。

## 8. 权限与数据范围

权限模型由 RBAC、ABAC、Data Scope、Field Permission 和 Action Permission 共同组成。

### 8.1 数据范围

- 平台超级管理员可管理平台级配置和租户。
- 租户管理员只访问本租户数据。
- 学校管理员只访问授权学校数据。
- 年级主任只访问授权年级、班级和考试。
- 教师只访问自己班级、课程或分配考试。
- 阅卷员只访问分配的题目或任务，默认不可见学生身份。
- 仲裁员只访问分配的仲裁任务。
- 学生只访问自己的成绩、反馈和申诉。
- 审计员只读授权范围内的审计日志。

### 8.2 字段权限

姓名、学号、身份证号、成绩、私密备注、申诉内容和导出文件必须支持字段级权限和脱敏显示。

### 8.3 操作权限

导出成绩、发布成绩、批量改分、Rubric 锁定、权限变更、数据删除和归档必须单独授权。

## 9. 审计与合规

系统必须审计以下行为：

- 登录、登出、失败登录。
- 文件上传、下载、删除。
- 考试创建、修改、状态流转、归档。
- 题目、答案、Rubric、评分策略修改。
- OCR 任务、AI 评分、证据校验、人工复核、仲裁。
- 改分、成绩确认、成绩发布、成绩导出。
- 申诉提交、处理、改分。
- 权限、角色、数据范围调整。

审计日志必须记录 actor、action、target、before、after、reason、ip、user_agent、created_at。审计日志不可通过普通业务接口修改或删除。

## 10. 私有化部署要求

- 支持内网部署。
- 支持 Docker Compose 起步，预留 Kubernetes/Helm。
- 支持 PostgreSQL、Redis、MinIO、Qdrant。
- 支持本地模型、私有化模型和外部模型可配置。
- 支持备份恢复、健康检查、日志查看、版本回滚和许可管理。
- 支持 HTTPS/mTLS、对象存储加密、数据库备份和数据保留策略。

## 11. Windows EXE 客户端要求

EXE 客户端定位为扫描工作站、教师离线阅卷端和本地同步客户端。

必须支持：

- 服务端地址配置。
- 登录与设备绑定。
- 批量选择 PDF/图片作为扫描上传输入。
- 上传队列、进度、失败重试、断点续传预留。
- 离线阅卷任务包下载、草稿保存和联网同步。
- 本地缓存加密或安全存储抽象。
- 冲突检测：服务端已提交、Rubric 版本变化、任务撤回。
- 本地日志、系统诊断、自动更新预留。

不得实现假扫描仪能力。扫描仪接入未完成时必须显示“待接入”。

## 12. 报告与数据分析

### 12.1 学生报告

- 总分、题目得分、知识点掌握。
- 教师反馈、可见批注、错因分析。
- 是否展示排名由学校策略控制。
- 申诉入口和申诉期提示。

### 12.2 教师报告

- 班级平均分、及格率、优秀率。
- 分数段分布、题目得分率、高频错误。
- 知识点薄弱项和讲评建议。
- 分层辅导名单。

### 12.3 管理者报告

- 年级对比、班级对比、学科趋势。
- 试卷难度、题目区分度、客观题选项分布。
- 阅卷一致性、AI 采纳率、人工改分率、仲裁数量。
- OCR 失败率、异常成绩预警、申诉统计。

## 13. 企业版验收标准

### 13.1 产品功能

- 能创建正式考试。
- 能上传试卷并配置题目、分值、答题区域和 Rubric。
- 能批量采集答卷并记录质量问题。
- 能创建 OCR 任务并保存 OCR 结果。
- 能切分答案段。
- 能生成 AI 建议分和证据。
- 能人工复核和双评仲裁。
- 能确认、发布、导出成绩。
- 能处理学生申诉。
- 能生成学生、教师和管理者报告。
- 能审计所有关键操作。

### 13.2 工程能力

- 支持私有化部署。
- 支持 Windows EXE 客户端。
- 支持多租户和权限隔离。
- 支持任务队列、失败重试和状态查询。
- 支持备份恢复、日志、监控和健康检查。

### 13.3 AI 能力

- 每个 AI 分数有证据。
- 每个 AI 输出有 model_version、prompt_version、rubric_version。
- 每次评分可回放。
- 低置信度自动转人工。
- AI 不能直接覆盖最终成绩。
- 支持评估集和质量指标。

### 13.4 合规能力

- 学生身份可脱敏。
- 成绩访问可控。
- 导出有权限、审批、审计和水印。
- 改分可追溯。
- 数据支持归档和删除策略。

## 14. 非目标范围

- 不做纯 EXE 单机软件。
- 不做通用 OCR 工具。
- 不做只有 AI 聊天框的批改工具。
- 不默认做摄像头监考、锁屏监控或高强度远程监考。
- 不在没有真实能力时包装成真实 OCR、真实 AI 或真实扫描仪接入。
- 不把学生数据默认用于模型训练。

## 15. 未来扩展方向

- 第三方教务系统、LMS、题库系统集成。
- 更完整的公式识别和手写数学推理。
- 样例库驱动的相似答案分组。
- 高级考试质量分析和测量学指标。
- 多语言和国际化。
- 更完整的 Tauri EXE 安装、更新、远程诊断和企业分发。
- Kubernetes 多节点部署、灰度升级和跨区域灾备。
