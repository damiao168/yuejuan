# STORY-061B1C1 持久化沙箱审批治理实现复审（2026-07-30）

## 结论

通过。沙箱准入证据已经从一次性函数参数升级为租户隔离、供应商与部署精确绑定、可过期且显式可撤销的治理记录。该切片没有注册外部 Adapter、没有读取或保存真实 Secret、没有产生网络请求，也没有放开学生数据外发。

## 实现范围

- 新增 `model_sandbox_approval` 数据表，审批事实不可编辑，只允许创建和显式撤销。
- 审批记录精确绑定租户、外部供应商、DashScope 原生协议、部署和区域。
- 批准期限必须大于当前时间且不超过 90 天；同一部署同一时刻只能存在一条未撤销审批。
- 合同、留存、数据区域、价格、沙箱账号和仅合成数据均为数据库强制事实；图片外发单独批准。
- 记录中不包含 Secret 引用、Secret 值、请求体、图片或学生身份信息。
- 新增审批历史查询、创建和撤销 API；请求使用严格 JSON。
- 查看复用 `model:read`，创建与撤销复用 `model:provider:manage`。
- 创建与撤销都写入操作审计，审批理由只进入审计，不在资源响应中回显。
- `AssessStoredSandboxAdmission` 在原有运行时门禁上继续校验审批的租户、供应商、部署、键值和有效期绑定；运行时 Secret 探测仍独立执行。

## 安全与失败关闭

- 跨租户供应商、部署或审批 ID 对调用方表现为不存在。
- 非外部供应商、非 `dashscope_native`、区域不一致、证据不完整或超期审批均被拒绝。
- 重复有效审批冲突；撤销后的历史保留，重复撤销冲突；只有显式撤销后才能创建替代审批。
- 数据库通过复合外键、检查约束和部分唯一索引重复执行核心边界，避免只依赖 Handler。
- 平台跨租户操作的真实操作者保留在操作审计中，不伪造目标租户用户外键。

## 测试覆盖

- 输入完整性、期限和审批证据转换。
- Memory Store 的租户隔离、库存绑定、重复审批、撤销和历史保留。
- Handler 严格 JSON、创建/查询/撤销、权限路由和审计动作。
- 已存审批与运行时供应商、部署、租户及有效期的精确绑定。
- PostgreSQL E2E 覆盖创建、查询、重复冲突、撤销、替代审批、跨租户失败关闭和数据库不完整事实约束。
